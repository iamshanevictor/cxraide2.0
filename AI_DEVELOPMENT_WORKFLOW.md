# AI-assisted development workflow

1. Start with `AGENTS.md`, `SESSION.md`, the selected `READY` task in `PROJECT_TASKS.md`, relevant sources/tests, and Git status. Ask for a missing owner decision only after completing independent discovery. Do not repeatedly scan the full repository.
2. Use one active queue. Each task has a bounded objective, explicit acceptance/validation, and an exact proposed commit message containing its task ID. Include that message in every task completion report, whether or not a commit is made. Move a dependent task to `READY` only after its prerequisite evidence is recorded. Keep local completion separate from hosted or owner acceptance. Archive completed task detail so the live queue stays short; do not invent replacement work when it is empty.
3. Characterize existing behavior with synthetic data, then make a small vertical change. Validate the owning boundary, integration behavior, and applicable release gate. Prefer direct modules and contracts to speculative layers.
4. Route to the lowest capable model available in this Codex environment: Luna · Low for bounded extraction/mechanical work; GPT-6.1 Sol · Low for ordinary scoped implementation; GPT-6.1 Sol · Medium for architecture, cross-layer behavior, identity, migrations, or integrity. Use GPT-6 Astra only for a concrete unresolved conflict. Verify model availability when selecting the route. Use deterministic commands for routine checks.
5. Record a consequential choice in `docs/architecture/DECISIONS.md`, a concise handoff in `SESSION.md`, and evidence in the task. Keep secrets and real personal data out of prompts, tests, logs, screenshots and commits. Do not commit automatically or perform owner-operated cloud/destructive actions.

Official [OpenAI model-selection guidance](https://developers.openai.com/api/docs/guides/model-selection) recommends checking representative outcomes and using the lightest adequate setting. The named Luna, GPT-6.1 Sol and GPT-6 Astra routes were available to this Codex environment at bootstrap; recheck availability if the environment changes.
