Assessed from source on 2026-10-27 and updated after CX-004/005/011/013. **Observed** means a code path exists, not that it passed browser or hosted testing. The owner-stated target is a public, research-only demo with dataset sample images, annotation, and clearly simulated results, without storing identifiable patient images or reports.

## Simulation and contract findings

- CX-011 changed the public demo action, overlay, result panel, and report to identify preset browser simulation and avoid model/confidence claims. Findings are fixed and repeatable; they do not analyze pixels. Manual expert boxes remain interactive and local to the page. [Demo UI](../../client/src/views/DemoWorkspaceView.vue), [fixture](../../client/src/services/demoSimulation.js).
- `ModelService` still has the old server-prediction and random fallback path for callers outside `/demo`; that legacy method and Flask endpoint were not removed or secured by CX-011. Do not expose the Flask upload route publicly without a separate review.
- The selector sends `CXR-IT2` and `CXR-IT3`, while Flask checks `model_type == 'it2'` after lowercasing; both selector values enter the combined branch in source. A later unconditional `predictions = predict(image_tensor)` also overwrites the IT2-specific result. CX-003 tests characterize both defects; a repair is separate work. [Selector](../../client/src/views/DemoWorkspaceView.vue), [server mode branch](../../server/model_service.py), [tests](../../server/tests/test_prediction_contract.py).
- Mock configuration does not guarantee a working server mock when PyTorch is absent: the endpoint returns its PyTorch error first, and the browser fallback depends on that exact error text. [Endpoint](../../server/model_service.py), [fallback](../../client/src/services/modelService.js).

## Privacy and verification boundary

**Observed:** CX-004 removed the demo's automatic image and filename storage; CX-005 removed visitor upload controls; CX-011 removed the public demo's prediction request. The public demo now creates fixed results in the browser and retains them only in component memory. The separate unauthenticated Flask endpoint still accepts supplied images if called directly; the inspected route has no explicit byte or decoded-pixel limit and returns image data URLs. No persistent server write was found in that route. These observations do not establish a particular host's logging, caching, or retention. [Demo view](../../client/src/views/DemoWorkspaceView.vue), [client request service](../../client/src/services/modelService.js), [server route](../../server/model_service.py).

**Inference:** The public `/demo` prediction experience no longer needs a backend. Static hosting is now feasible for this route if the rest of the public SPA also has no required API dependencies; that site-wide dependency audit and deployment preview remain release gates.

**Not verified:** Manual browser interaction, network panel, actual PDF rendering, box responsiveness at different viewport sizes, deployment or host retention, exact mapping of the attached sample to one of the two dataset links, and mapping to the separate research repository. Manual testing is deferred by owner request until planned development is complete. Automated contract tests verify fixture output, sample wiring, and that the demo method does not call the prediction service. The sample is used solely to demonstrate annotation; preset findings do not analyze it.

## Decision inputs for CX-002

1. Visitor upload: approved samples only, or visitor uploads with a non-identifiable-image rule and safeguards?
2. Browser retention: explicit opt-in, or no image retention between visits?
3. Hosted simulation: browser-only simulation, or hosted mock API? Compare result provenance, privacy and free-hosting fit.
4. Sample and model labeling: identify approved chest X-ray samples and rights; decide how IT2/IT3 names should appear for simulations. Record the research repository link and metric mapping.
